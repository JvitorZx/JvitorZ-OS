# DEVELOPMENT_GUIDELINES

## Princípios do Projeto

- O Dashboard é apenas a Home.
- Operadores são os locais de trabalho.
- A Sidebar é fixa.
- Não existe botão "Voltar" na versão final.
- Componentes devem ser reutilizados.
- Nenhum operador cria componentes exclusivos sem justificativa.
- Toda funcionalidade precisa resolver um problema claro.
- UX vem antes de novas funcionalidades.
- Arquitetura não pode ser alterada sem documentação.

## Fluxo de Desenvolvimento

Toda sprint deve seguir:

1. Discussão
2. Arquitetura
3. UX
4. Implementação
5. Testes
6. Documentação
7. Git

## Padrões

- Componentização obrigatória.
- Tema único.
- Nomenclatura consistente.
- Estrutura modular.

## Critérios para considerar uma sprint concluída

- Funciona.
- Foi testada.
- Foi documentada.
- Não quebrou funcionalidades existentes.
